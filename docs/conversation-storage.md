# 对话持久化

数据库连接、Prisma schema、迁移及生成的客户端都由 `apps/server` 持有。CLI 只依赖
Hono RPC 的类型和 HTTP API，不访问数据库，也不持有数据库凭据。当前没有其他直连数据库的
应用，因此不创建共享数据库包。

| 表 | 作用 | 关键字段与约束 |
| --- | --- | --- |
| `conversations` | 区分线性对话 | UUID、标题、最后活动时间、事务内分配的消息序号 |
| `messages` | 保存用户和 AI 消息 | 消息 ID、对话 ID、序号、角色、完整 UIMessage `parts` JSONB、metadata、schema_version |
| `generation_runs` | 记录一次服务端生成 | 请求 ID、输入/输出消息 ID、模型、状态、错误、用量、结束原因、心跳和起止时间 |

`parts` 保存文本、推理、工具调用及结果（包括工具错误），保留片段的顺序和 SDK 状态。
不为每个文本增量创建数据库事件。生成级错误、取消和中断保存在 `generation_runs.error`，
历史页面在对应 AI 消息下展示；CLI 本地网络或解析错误不持久化。

生成状态为 `running / completed / failed / cancelled / interrupted`。消息的完成状态以对应
run 为准，不从文本片段的 `state` 推断。下一轮上下文包含用户输入和 `completed` AI 消息，
取消、失败或中断后的部分 AI 消息仅用于历史展示。

请求体为 `{ conversationId, requestId, message }`，只接受新的用户文本消息。历史从数据库读取，
客户端不能重写已有消息。`requestId` 使用该用户消息的 ID；重复请求返回 409，保留原记录，
不追加消息或再次调用模型。用户需要重新打开对话查看原请求结果。

创建生成的事务锁住对话行，分配两个连续序号并保存用户输入、预留 AI 消息和 run。
PostgreSQL 部分唯一索引另外保证同一对话最多一个 `running` run。复合外键保证输入/输出
消息属于同一对话。检查约束保证序号为正数、parts 为数组、终态具有结束时间。
这些 SQL 约束在迁移中维护，修改 schema 时须保留。

生成中通过 SDK 的 `readUIMessageStream` 获取完整消息快照，每约一秒串行写入消息和心跳。
正常完成或取消时，等待所有快照写入，再事务保存最终消息和状态。数据库快照写入失败会
停止生成。强制杀进程时允许丢失最后约一秒内容；这是数据库正常可用时的目标，并非实时保证。

失去心跳超过 90 秒的 `running` run，在读取历史或提交下一条消息时回收为 `interrupted`。
该余量大于模型的 60 秒生成超时，避免误回收其他服务进程的正常请求。服务端收到 SIGINT
或 SIGTERM 时取消活动生成、等待最终保存，然后关闭连接池。

本地 Compose 使用 PostgreSQL 18、命名卷和仅监听 `127.0.0.1:54324` 的端口。`db:down`
保留卷。独立的 `freecode_test` 数据库由初始化 SQL 创建，测试脚本自动应用迁移；测试仅
删除自己创建的对话，不清空开发库。自定义 `TEST_DATABASE_URL` 的数据库须提前创建且名称
以 `_test` 结尾。

当前历史入口展示最近 50 条对话。尚未接入用户、鉴权、消息编辑或对话分支。
