# TODO：恢复历史对话最后一次提交的模式

**状态：待评估，尚未实现。** 本文记录候选方案，后续可调整语义、保存时机与回退策略；评估通过后再修改实现代码。

## 问题与目标

当前模式由 `apps/cli/src/app/routes.tsx` 的 `AppRoutes` 统一持有，首页和聊天页使用同一份选择。打开历史对话时，会沿用当前界面的模式，而非该对话最后一次提交时的模式。

当前数据库的 `Conversation`、`GenerationRun` 和会话详情契约均未保存模式，无法可靠恢复。不能根据历史是否出现写工具推断模式：构建模式也可能只读取文件。

目标：打开历史对话时，恢复该对话最后一次被服务端接受的提交所使用的模式；首页模式仅决定新对话的初始模式。继续允许用户在对话中切换下一轮的模式。

## 建议语义与待评估事项

- [ ] 确认采用“最后实际提交的模式”，而非“最后选择但未提交的模式”。建议前者：切换后没有发送消息，不更新持久化记录。
- [ ] 确认提交被接受的边界。建议以保存用户输入并创建生成记录的事务成功为准；请求校验失败、对话忙或事务失败不更新模式。
- [ ] 确认生成失败、取消或意外中断仍保留本轮提交模式，不等到生成成功才保存。
- [ ] 确认旧会话缺失模式时回退到 `readOnly`。这是建议策略，需评估后确定；不从自然语言或工具记录猜测旧模式。
- [ ] 确认首页默认选择与已有会话选择分开；在历史会话内切换模式不反向覆盖首页选择。
- [ ] 本方案不改变正在生成的请求权限。生成中切换模式仍只影响后续提交；若要立即停止构建轮次，另行评估。

## 最小实现方案

1. **持久化会话模式**
   - 在 `Conversation` 增加可空的 `lastMode` 字段，旧记录保持缺失，避免把未知历史模式伪装成已知值。
   - 将经过 `agentModeSchema` 校验的模式传入 `beginGeneration`，在现有保存输入、创建生成记录的事务中同步更新 `lastMode`。
   - 重复请求或被拒绝请求不应覆盖记录；不在生成结束时再次回写模式，避免旧生成覆盖后续选择。
   - 暂不额外给每个 `GenerationRun` 保存模式；只有实际需要逐轮审计时再扩展。

2. **扩展会话详情契约**
   - `packages/contracts/src/conversation.ts` 的会话详情增加 `lastMode`，以现有 `agentModeSchema` 校验，并兼容旧数据缺失。
   - `apps/server/src/features/conversations/store.ts` 的详情响应返回该字段；列表接口无需为本需求增加字段。
   - 客户端通过现有会话读取和校验链获取模式。

3. **调整 CLI 状态归属与初始化**
   - 首页保留自己的新对话模式；已有会话的待提交模式由聊天页的实际使用者持有。
   - 打开历史会话时，依据加载到的 `lastMode` 初始化；新会话首轮继续使用导航时已校验的 `promptMode`。
   - 每个会话只在初始化时恢复一次，后续刷新或同步消息不能覆盖用户当前的待提交选择。
   - 切换会话时清理旧请求，避免较晚返回的旧会话数据覆盖当前模式。
   - 按实际生命周期判断是否需要 hook，不为单个模式状态单独增加抽象。

4. **保持每轮权限执行逻辑**
   - 提交时明确发送当前选择的模式，服务端继续运行时校验并选择对应 Agent。
   - 保持当前工具白名单与未授权历史工具片段过滤；恢复界面模式不能替代服务端权限约束。

## 验收条件

- [ ] 首页为构建时，打开最后提交模式为只读的历史对话，显示只读，下一轮请求携带 `readOnly`。
- [ ] 首页为只读时，打开最后提交模式为构建的历史对话，显示构建，下一轮请求携带 `build`。
- [ ] 在模式不同的历史对话之间切换，各自恢复正确，重新启动 CLI 后仍有效。
- [ ] 只切换模式而未提交，离开并重新打开时恢复最后提交模式。
- [ ] 服务端接受提交后，即使生成失败、取消或中断，重新打开仍恢复该次提交模式。
- [ ] 无效模式、重复请求及忙碌时被拒绝的请求不改变已保存模式。
- [ ] 旧会话按评估确定的回退策略打开，缺失模式不会导致加载失败。
- [ ] 新会话首轮使用首页提交时的模式；历史会话的选择不覆盖首页默认选择。
- [ ] 消息刷新、旧请求晚到和快速切换会话不覆盖当前待提交选择。
- [ ] Tab 切换、修饰键、加载、错误显示及离开页面清理通过模拟响应交互测试。
- [ ] 只读工具白名单、历史过滤和模型主动返回写工具调用时拒绝执行的行为保持有效。
- [ ] 按仓库约定完成服务相关路由和 `/health` 验证、CLI 显示及热重载和退出后的终端恢复验证，并运行 `bun run check`；如实记录限制。

## 调研依据

调研日期：2026-10-03。以下源码链接固定到本次查看的提交，行为限定到所列客户端。

- **Roo Code：任务级最后保存的选择。** 切换模式时先更新任务历史，打开历史任务时恢复 `historyItem.mode`，并检查模式是否仍存在。其保存时机与本方案不同：未提交的切换也会保存。[恢复与切换源码](https://github.com/RooCodeInc/Roo-Code/blob/b867ec9145750d0ae1ff7f02d35406e9bf2a0b16/src/core/webview/ClineProvider.ts#L843)。该仓库已归档，作为设计先例参考。
- **OpenCode ACP：会话保存值优先，历史消息回退。** 恢复顺序为有效的会话 Agent、历史消息 Agent、默认 Agent。[恢复源码](https://github.com/anomalyco/opencode/blob/907b3bc518fa48e90e8ec24dd327d13eee71c36c/packages/opencode/src/acp/service.ts#L1089)。
- **OpenCode 桌面/Web：按会话保存选择。** 缺少已保存选择时，从最后一条用户消息初始化 Agent 与模型。[状态与恢复源码](https://github.com/anomalyco/opencode/blob/907b3bc518fa48e90e8ec24dd327d13eee71c36c/packages/app/src/context/local.tsx#L397)。
- **Cline VS Code：全局模式对照。** 恢复任务生成配置时读取全局 Plan/Act 设置，说明同类项目没有统一采用会话模式恢复。[恢复源码](https://github.com/cline/cline/blob/39ff2359f7e08231281539696e48a166ce49270c/apps/vscode/src/sdk/sdk-task-resume.ts#L49)。
- [OpenCode 官方 Agent 文档](https://opencode.ai/v2/docs/agents)：默认 Agent 与已有会话保存的 Agent 分开；其 Plan 权限语义不等同于 FreeCode 的严格只读。
