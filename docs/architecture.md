# 项目结构决策

本次调整按职责聚合代码，保持现有 API 路径、模型、工具名称、数据库结构和服务端容器执行方式。
不是所有模块都需要拆成 `schema.ts` 与 `runtime.ts`：这种结构适合同时具有外部输入契约和独立执行过程的工具。

## 全项目评估

| 范围 | 决策 | 原因 |
| --- | --- | --- |
| Agent 定义与工具 | 提取到 `packages/agent` | 从鉴权、供应商配置和应用业务中分离执行能力 |
| 工具实现 | 每个工具聚合 schema/runtime | 定义与实现就近维护，worker 只分发，不集中维护六个实现 |
| 容器与工作区防护 | 放在 Agent 包的独立沙箱入口 | 与工具紧密协作，但不能从共享入口加载，也不能交给 CLI 直接执行 |
| 会话契约 | 提取到 `packages/contracts` | 服务端和 CLI 已实际使用同一请求、响应和状态定义 |
| 服务端会话存储及生成 | 聚合到 `features/conversations` | 都属于会话生命周期，留在应用中管理数据库与持久化策略 |
| 模型供应商 | 放在 `src/providers` | 模型身份、密钥检查和错误映射需要共同维护 |
| HTTP 路由与 app | 保留现有分层 | 请求校验、路由组合与业务实现已经分开；SSE Response 由路由创建 |
| 数据库与 Prisma 迁移 | 保留在 server | 只有一个应用访问数据库，不建立共享数据库包 |
| CLI 会话 API | 提升到 `lib/conversationApi.ts` | 首页创建与聊天/历史读取属于跨功能实际复用 |
| CLI 传输 | 从聊天 hook 提取到 `features/chat/transport.ts` | 协议检查独立于 React 状态，便于模拟 SSE 验证 |
| CLI 页面、组件及 hook | 保留原有功能分层 | 展示、交互、请求生命周期已经有明确边界 |
| 配色、输入 schema 和按键 | 保留在 CLI lib | 已被首页和聊天实际共用，不需要独立 UI 包 |
| 应用入口、本地后端启动器 | 保留应用所有权 | 终端、监听和父子进程清理由应用管理；当前没有发布安装包需求 |
| 根配置及数据库/测试脚本 | 保留根目录 | 已统一工具链和初始化流程，不为短脚本增加模块层级 |

## 依赖边界

- `apps/server` 使用 `@freecode/agent/server`、`@freecode/agent/sandbox` 和 `@freecode/contracts`。
- `apps/cli` 使用 `@freecode/contracts`、SDK 客户端及 OpenTUI，通过 HTTP/SSE 消费后端。
- CLI 保留对 `@freecode/server` 的 `AppType` 类型引用；这不启动后端或加载数据库。
- 公共包不反向引用应用。Agent 包不依赖 Hono、Prisma、React 或模型供应商包。
- `@freecode/agent` 根入口及工具 schema 只使用 Zod 和环境无关的校验。
- SDK 工具通过 `Sandbox.execute` 委托执行，`tools/runners.ts` 仅供容器入口和临时目录测试调用。
- 共享 schema 不导入运行实现；worker 不导入 Agent、SDK 工具适配或供应商。
- CLI feature 可依赖 lib，lib 不依赖 feature；服务端 feature 不互相引用，也不依赖路由。

包的公开入口由 `exports` 限定。没有当前用途的客户端工具执行入口、插件注册框架或共享 UI 包不创建。

## 迁移时需要保持的约束

- 共享入口必须能够单独用于浏览器，不能间接加载文件系统、Bun、供应商或数据库；由浏览器打包测试验证。
- 工具名称、输入/输出和 SDK 消息协议关系到已保存的历史。后续修改契约时，需要同时验证旧记录读取、上下文转换与 CLI 展示。
- worker 的打包入口与相对路径随目录迁移更新；真实容器测试验证镜像内依赖、挂载、取消和后台进程清理。
- 会话事务、工作区过滤、并发锁和快照队列继续由服务端维护；公共包只接收执行所需的模型与沙箱。
- 包路径变化不能引入重复运行时或初始化副作用。配置加载、数据库连接池及进程清理仍由应用管理，热重载也需要验证公共包的修改。

## 新增工具

1. 在 `packages/agent/src/tools/<工具名>/schema.ts` 定义描述与 Zod 输入/输出契约。
2. 在同目录 `runtime.ts` 实现容器内执行；复用现有路径检查、文件限制和输出截断。
3. 在 `tools/schemas.ts` 注册契约，在 `tools/runners.ts` 注册实现，在 `server.ts` 绑定 SDK 工具。
4. 用临时目录或模拟执行器验证输入、输出和取消；涉及进程或挂载时补真实容器验证。

工具键名也是历史消息协议的一部分。移动目录不改名；删除或重命名工具时验证旧记录的展示与 SDK 历史转换。

## 生命周期与验证

服务端入口加载安装位置的 `.env`，组合应用运行时。Agent 工厂只接收模型与 Sandbox，
不自行加载配置、启动容器、注册进程监听或结束进程。供应商的模型实例和存储身份从同一配置产生。

会话生成继续每约一秒串行保存快照，终态等待队列后写入；取消、失败和意外断流保留部分内容。
活动生成记录继续使用服务端进程内的热重载共享 Map；每个 CLI 启动独立后端进程，退出取消该进程的生成。
生成总超时与失联回收余量集中在会话功能中维护。数据库锁、部分唯一索引和工作区校验不移动到能力包。

根目录执行 `bun run check`，包括四个 workspace 的类型检查、独立测试库初始化和所有测试。
Agent 共享入口另有浏览器打包验证，工具测试覆盖真实容器，模型循环与 CLI 流协议使用模拟响应。
CLI 入口或请求生命周期调整后，还需在交互式终端验证启动、热重载与退出恢复。
